# Stratum-Flow Blog Ops Skill

このスキルは、Stratum-Flow向けのブログ記事を「検索流入を取りにいく運用単位」で作成するための実務ガイドです。

単なる本文生成ではなく、以下を必須で実行します。

- 検索意図を踏まえたキーワード設計
- SERPで勝てる見出し構成
- 読了率とCV導線を両立した本文
- アイキャッチ画像の必須化
- 公開後のリライト前提の運用メモ

## 目的

- Stratum-Flowの認知獲得（TOFU）
- 比較検討層の刈り取り（MOFU）
- 指名検索・問い合わせ増加（BOFU）

## 入力として確認すること

記事作成前に、足りない情報があれば先に確認する。

- 記事の目的: 認知 / リード獲得 / 既存顧客教育
- 想定読者: 役割、業界、課題、知識レベル
- 訴求するStratum-Flowの価値: 何を他より優位に見せるか
- 主要キーワード候補: 1つの主軸 + 2-5個の関連語
- CTA: 問い合わせ、資料DL、デモ依頼、メルマガ登録など

## 必須品質要件

以下を満たさない場合、納品しない。

1. SEO要件
- 主キーワードを1つに絞る（記事の検索意図を分散させない）
- タイトルに主キーワードを自然に含める
- H2に関連語を分散し、過剰な同語反復を避ける
- 導入文120-180文字で「誰の何を解決するか」を明示
- メタディスクリプションを100-140文字で作成
- URLスラッグ案を短く提示（英小文字 + ハイフン）

2. コンテンツ要件
- 見出しは結論先出しで、各節に実務価値を置く
- 抽象論を避け、手順・判断基準・失敗例を入れる
- 箇条書きと表現のリズムを使って可読性を上げる
- E-E-A-Tを補強する情報（経験、実績、具体例、比較軸）を含める
- 最後に明確なCTAを1つ配置

3. 画像要件（必須）
- アイキャッチ画像を必ず1点用意する
- 本文中にも必要に応じて図版案を提示する
- アイキャッチについて以下をセットで出す
	- 画像コンセプト
	- 生成用プロンプト（16:9）
	- 代替テキスト（alt）
	- ファイル名案（SEO配慮、英小文字ハイフン区切り）

4. ブランド要件
- Stratum-Flowのトーンに合わせて、過剰な煽り・断定を避ける
- 誇張表現を使わず、検証可能な主張に寄せる
- 競合比較は中立で、根拠のない優劣断定をしない

## 記事作成フロー

1. 検索意図と読者課題を定義
- 主要クエリの意図を分類（情報収集 / 比較 / 導入検討）
- 読者の「直前行動」と「次に取りたい行動」を言語化

2. キーワードクラスタを設計
- 主キーワード1つ
- 関連語2-5個
- 共起語・言い換え語を過剰でない範囲で散らす

3. SERP想定で構成を作る
- H1はベネフィット中心で具体化
- H2は疑問解消順に並べる
- H3は手順、条件分岐、注意点を分解

4. 本文執筆
- 冒頭で結論と対象読者を提示
- 各節は「要点 -> 根拠 -> 実行方法」の順で記述
- 必要に応じてチェックリスト化

5. 視覚要素を作成
- アイキャッチ生成指示を作る（必須）
- 図解候補がある場合は本文差し込み位置を指定

6. 公開前最終チェック
- タイトル、メタ、スラッグ、見出し階層、CTA、altを確認
- 不自然なキーワード詰め込みを除去
- 1スクロール目で読者メリットが伝わるか確認

## 出力フォーマット

最終出力は以下の順で提示する。

1. 記事戦略サマリー
- 目的
- 想定読者
- 主キーワード / 関連語
- 想定検索意図

2. SEOメタ情報
- タイトル案（32文字前後を推奨）
- メタディスクリプション（100-140文字）
- URLスラッグ案

3. 記事本文（Markdown）
- H1-H3を含む完成稿
- 適切な箇条書き
- 最終CTA

4. アイキャッチ仕様（必須）
- コンセプト
- 画像生成プロンプト（16:9）
- altテキスト
- 推奨ファイル名

5. 公開後運用メモ
- 初回リライト観測ポイント（CTR、滞在、CV）
- 2週間後に見直す見出し候補

## 禁止事項

- 根拠のないNo.1表現
- 医療・法律・金融などでの断定的助言（必要なら注意書きを入れる）
- キーワードを不自然に連呼するSEOスパム的文章
- 画像要件を省略した納品

## 実行時の短縮チェックリスト

- 主キーワードは1つに絞れているか
- タイトル・導入・H2に意図が通っているか
- 本文は具体的な行動に落ちるか
- CTAは単一かつ明確か
- アイキャッチのコンセプト、プロンプト、alt、ファイル名を出したか
